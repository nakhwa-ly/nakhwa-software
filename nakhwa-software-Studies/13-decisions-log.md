## ✅ القرارات الأولية (قبل البدء)

### 2026-05-19 — اختيار Next.js 14 (App Router)
**القرار:** استخدام Next.js 14 مع App Router
**السبب:**
- دعم RSC (React Server Components) لأداء أفضل
- SEO ممتاز out-of-the-box
- next-intl يدعم App Router بشكل أصلي
- النشر على Vercel سلس

**البدائل المرفوضة:**
- **Vite + React:** ضعيف في SEO، يحتاج SSR إضافي
- **Astro:** ممتاز لكن أقل ديناميكية للنماذج
- **Flutter Web:** bundle size ضخم، SEO ضعيف
- **HTML + JS عادي:** بطيء التطوير، صعب الصيانة

**التأثير:** هيكل المشروع و routing يعتمدان على App Router conventions.
**مَن اتخذه:** مشترك

---

### 2026-05-19 — اختيار next-intl لـ i18n
**القرار:** استخدام `next-intl` بدل `next-i18next` أو `react-i18next`
**السبب:**
- دعم أصلي لـ App Router
- API بسيط ومتسق
- يدعم RTL وانعكاس الاتجاه
- تكامل مع SSR و RSC

**البدائل المرفوضة:**
- **next-i18next:** لا يزال يعتمد على Pages Router
- **react-i18next:** لا يدعم SSR بسلاسة
- **بناء custom:** إعادة اختراع العجلة

**التأثير:** ملفات الترجمة في `messages/`، middleware للـ routing.
**مَن اتخذه:** مشترك

---

### 2026-05-19 — اختيار Framer Motion للأنيميشن
**القرار:** استخدام `framer-motion@11+`
**السبب:**
- الأقوى والأشهر في React
- توثيق ممتاز
- `whileInView` يحل scroll animations
- يدعم RTL مع modifications

**البدائل المرفوضة:**
- **GSAP:** قوي لكن بعض الميزات مدفوعة
- **React Spring:** API أصعب
- **CSS فقط:** محدود للأنيميشن المعقد

**التأثير:** كل مكون متحرك يستخدم Framer Motion APIs.
**مَن اتخذه:** مشترك

### 2026-05-19 — اختيار Zod للـ Validation
**القرار:** استخدام `Zod` مع `@hookform/resolvers`
**السبب:**
- تكامل مثالي مع TypeScript
- Type inference تلقائي
- صيغة واضحة
- شائع في النظام البيئي

**البدائل المرفوضة:**
- **Yup:** يحتاج تعريفات types يدوية
- **Joi:** أكثر استخداماً في Node backend
- **Custom validators:** صعب الصيانة

**التأثير:** كل schema validation في `lib/validations.ts`.
**مَن اتخذه:** مشترك

---

### 2026-05-19 — اختيار Cairo + Inter للخطوط
**القرار:** Cairo للعربية، Inter للإنجليزية
**السبب:**
- **Cairo:** خط عربي حديث، قابل للقراءة، يدعم أوزاناً متعددة
- **Inter:** خط لاتيني نظيف، شائع في المواقع الحديثة
- كلاهما متاح مجاناً على Google Fonts
- Performance ممتاز مع `next/font/google`

**البدائل المرفوضة:**
- **Tajawal للعربية:** جيد لكن Cairo أكثر تنوعاً في الأوزان
- **Roboto للإنجليزية:** Inter أكثر حداثة
- **خطوط custom:** زيادة في الـ bundle size

**التأثير:** متغيرات CSS `--font-cairo` و `--font-inter`.
**مَن اتخذه:** Claude

### 2026-05-19 — استراتيجية URL للـ i18n
**القرار:** `localePrefix: 'always'` — `/ar/...` و `/en/...`
**السبب:**
- SEO أوضح لكل لغة
- يسمح بـ canonical URLs منفصلة
- يدعم hreflang tags
- لا confusion بين اللغات

**البدائل المرفوضة:**
- **`as-needed`:** اللغة الافتراضية بدون prefix → يخلط الـ analytics
- **Subdomain (`ar.nakhwa.com.ly`):** يعقّد الـ DNS والـ deployment
- **Query string (`?lang=ar`):** سيء لـ SEO

**التأثير:** كل link يجب أن يستخدم `Link` من `@/i18n/routing`.
**مَن اتخذه:** مشترك

### 2026-05-19 — الألوان الأساسية
**القرار:** Primary `#0066CC` (أزرق) + Accent `#D4AF37` (ذهبي)
**السبب:**
- الأزرق يوحي بالاحترافية والثقة (مهم لشركة تقنية)
- الذهبي يضيف لمسة فخامة وتميز
- التباين بينهما عالٍ وجميل
- يعملان جيداً في Light و Dark mode

**البدائل المرفوضة:**
- **أزرق فقط:** ممل
- **أحمر/برتقالي:** عدواني جداً لشركة B2B
- **بنفسجي:** trendy لكن غير مناسب للسوق الليبي

**التأثير:** CSS variables، Tailwind config، كل المكونات.
**مَن اتخذه:** مشترك

---

### 2026-05-19 — Mobile-First Responsive Strategy
**القرار:** تصميم mobile-first باستخدام Tailwind breakpoints
**السبب:**
- 60%+ من زوار المواقع في ليبيا يستخدمون الموبايل
- أسهل في التطوير (تبدأ بسيط ثم تضيف)
- Tailwind محسّن لهذا النمط

**البدائل المرفوضة:**
- **Desktop-first:** يجبرك على إلغاء styles على الموبايل
- **Adaptive (نسخ منفصلة):** كود مكرر

**التأثير:** كل CSS class يبدأ بدون prefix ثم يُضاف `md:` و `lg:`.
**مَن اتخذه:** Claude
